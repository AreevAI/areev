Coverage

83.6% of 76,211 instrumented source lines, from cargo llvm-cov --workspace --lcov. Enforced per crate — the Floor column above — plus a global floor of 75%. One workspace-wide number would let a regression in one crate hide behind a gain in another, and these crates do not carry the same risk.

Both filters are visible rather than hidden. On the same scope with test code counted back in the trace reads 86.8%; unfiltered — every instrumented line, which is what a naive cargo llvm-cov summary prints — it reads 82.1%. The published figure is the lowest of the three.

Test code is not scored against itself: tests/ and benches/ are excluded outright and #[cfg(test)] blocks line-by-line. Out of scope entirely, because this job cannot execute them:

  • crates/areev-py/ — PyO3 bindings — exercised by pytest in the `python` CI job, which this trace cannot see
  • crates/areev-bench/ — benchmark harnesses — explicit tools you run on purpose (`--bin honesty_metrics`), the same category as examples/
  • crates/areev-js/ — Node (napi) bindings — a STANDALONE package, not a cargo workspace member, so `--workspace` never builds it and it cannot appear in this trace at all; the `node` CI job builds and tests it separately
  • crates/areev-store/src/pg.rs — PostgreSQL backend — needs a live DATABASE_URL; the conformance runner covers it separately. Present in this build only because areev-py sets `default = ["postgres"]` and Cargo unifies features workspace-wide
